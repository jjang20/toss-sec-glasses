# PRD 결정 로그 (grilling)

이 문서는 grilling 세션에서 확정된 결정만 기록합니다. PRD 본문(`PRD.md`)은 이 로그를 근거로 작성합니다.
각 항목: 결정 · 이유 · 대안 · 트레이드오프 · 파생 영향.

---

## D1. 주 사용 상황 — 근무 중 "눈치 안 보는" 토스 사용

- **결정:** 근무 시간에 휴대폰을 꺼내 주식장을 확인하거나 거래하기 어려운 상황에서, 주변 사람에게 티 나지 않게 토스증권을 쓰는 것이 주 사용 상황이다.
- **이유:** 사용자가 직접 정의한 핵심 가치. 안경 화면은 착용자에게만 보이고, Neural Band 제스처는 손목 아래에서 작게 일어나 외부에서 거의 보이지 않는다 — 휴대폰 대비 이 기기만의 존재 이유.
- **대안:** (a) 이동 중 glance 중심 — 범용적이지만 "사회적 은밀함"이라는 차별점이 흐려짐. (b) 앉아서 집중 분석 — 휴대폰/PC가 더 낫다.
- **트레이드오프:** 사무실 맥락에 최적화하면 소리 내는 입력, 큰 손동작, 오래 응시하는 화면이 모두 불리해진다.
- **파생 영향 (후속 질문에서 확정 필요):**
  - 입력: 음성 명령은 사무실에서 "눈치"를 유발 → 입력 우선순위 재검토 (Q2)
  - 시선: 대화·업무 중 화면을 오래 보면 시선이 비어 보임 → 한 번 보기 시간 상한 필요
  - 거래 포함 확인됨 ("주식 거래") → 주문 플로우는 범위 안

## D2. 입력 우선순위 — Neural Band 단독 완결, 음성은 선택

- **결정:** 모든 기능(시세 확인, 이동, 주문 완료까지)은 Neural Band 제스처만으로 끝까지 수행 가능해야 한다. 텍스트 입력은 Neural Band 손글씨가 기본. 음성은 혼자 있을 때 쓰는 선택적 지름길이며, 음성이 없어도 불편하지 않아야 한다.
- **이유:** D1의 핵심 가치 "티 나지 않음"을 음성이 정면으로 깬다. 단일 입력으로 완결되면 설계 규칙도 단순해진다.
- **대안:** 음성 주 입력(사무실에서 사용 불가), 음성·제스처 동등(기능마다 기본 입력 결정 필요 → 복잡).
- **트레이드오프:** 종목명 입력이 느려진다(손글씨 < 음성).
- **파생 영향:** "종목을 고를 일 자체를 줄이는" 설계 필요 — 보유/관심 종목 중심의 즉시 접근. 제스처 어휘(gesture vocabulary)와 손글씨 입력의 실기기 리서치 필요.

## D2a. 핵심 플로우는 텍스트 입력 없이 완결 (D2 수정)

- **결정:** 종목 선택은 목록에서 고르기(보유·관심·최근 본 종목), 수량·가격은 스테퍼(좌우 스와이프). 손글씨는 목록에 없는 종목을 찾는 검색 보조 수단으로만 쓴다. 관심 종목 관리는 휴대폰 앱에서 한다.
- **이유:** 손글씨는 현재 영어(US)만 지원되고 실기기 검증 전이다. 텍스트 입력에 의존하지 않으면 언어 지원 여부와 무관하게 제품이 동작한다.
- **대안:** 손글씨 검색을 핵심 플로우로 두기 — 지원 범위에 제품이 종속됨.
- **트레이드오프:** 목록에 없는 종목은 안경에서 접근이 어렵다. D1(근무 중 아는 종목 확인)과 충돌하지 않는다.

## D3. 기본 언어는 영어

- **결정:** UI 기본 언어는 영어다.
- **이유:** 사용자 결정. 기기·손글씨 지원 언어(영어)와도 일치한다.
- **파생 영향:** 손글씨 검색이 영어 종목명으로도 가능해진다 — 토스 `GET /api/v1/stocks`가 국내 종목에도 `englishName`(예: Samsung Electronics)을 제공한다. 숫자·통화 표기(₩/$, 천 단위 구분), 등락 색상 관례(국내: 상승 빨강 / 미국: 상승 초록), 한국어 보조 로캘 여부는 후속 질문에서 확정.

## D4. v1 범위

- **결정:**
  - 핵심: 계좌 요약, 보유·관심 종목 시세, 빠른 주문(목록 종목 대상), 알림(목표가·체결 — 기술 검증 조건부)
  - **요약 카드로 포함:** 뉴스, 지수, 종목 히트맵 — 읽거나 훑는 화면이 아니라 "한 장으로 요약된 카드"로만 보여준다
  - 제외: 랭킹 목록 탐색, 긴 뉴스 본문 읽기, 자유 종목 탐색
- **이유:** 사용자 결정. 뉴스·지수·히트맵의 정보 가치는 유지하되, 오래 응시하는 형식(목록·본문)을 버려 D1과 양립시킨다.
- **트레이드오프:** 카드 한 장에 담을 정보를 강하게 요약해야 한다(뉴스 = 헤드라인 1~3개, 히트맵 = 섹터/종목 타일 소수).
- **리스크:** 알림 — 토스 API에 푸시 없음(서버 감시 필요) + Ray-Ban 웹앱의 백그라운드 알림 가능 여부 미확인 → 리서치 필수, 불가 시 v2.

## D5. 스크롤 대신 캐러셀 (탐색 원칙)

- **결정:** 자유 스크롤은 가장 피해야 할 경험이다. 콘텐츠는 **페이지 단위 캐러셀**로 배치한다.
  - 요약 카드(지수·히트맵·뉴스 등)는 **가로 캐러셀**
  - 길어지는 목록은 **세로 페이지 캐러셀**(TikTok처럼 한 번 스와이프 = 한 페이지)
  - 스크롤이 불가피하면 짧게 제한한다
- **이유:** 사용자 결정. 렌즈는 작고 시야 일부만 차지하며, EMG 스와이프 1회 = 이동 1단위가 예측 가능하다. 연속 스크롤은 "지금 어디까지 봤는지"를 잃게 하고 오래 응시하게 만든다.
- **대안:** 데모처럼 포커스 이동 + 자동 스크롤 — 위치 감각 상실, 반쯤 잘린 행.
- **파생 영향:** 모든 화면은 "페이지(카드) 단위"로 설계한다 → 디자인 시스템의 기본 단위가 카드/페이지가 된다. 페이지 위치 표시(인디케이터) 컴포넌트 필요.
